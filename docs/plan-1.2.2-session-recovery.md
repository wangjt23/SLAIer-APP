# 1.2.2 会话验证与自动登录分流

## 行为

1. 启动时读取真实考勤查询接口，以解析通过的响应确认会话可用。保留现有缓存展示与手动刷新，不将缓存登录状态当作重新提交密码的理由。
2. 自动恢复的候选状态仍为已过期/需要登录，但先重新验证实时考勤接口。接口可用就结束检查；网络故障、超时、普通 403 或未知响应不启动密码登录，也不暂停保存的凭据。
3. 实时确认会话失效后，用离屏 WebView 访问学校 SSO 入口，先仅使用已有 Cookie 续期。此阶段不解密或提交保存的账号密码，也不显示自动登录提示。
4. 只有学校真的展示可信登录表单、再次查询考勤接口仍明确过期，且用户允许自动登录时，才解密凭据并显示“正在自动登录”。成功后显示短暂的“登录成功”。
5. SSO 直接恢复成功时静默刷新考勤，不显示登录提示。单纯的会话检查成功不额外触发一轮刷新，避免刷新与验证相互触发。
6. 人机验证/密码登录失败继续提示自行登录并暂停密码尝试；已有失败暂停不会阻止只读验证或 Cookie 续期。手动登录成功后恢复后续密码自动登录能力。
