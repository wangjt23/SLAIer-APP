# 课表缓存与考勤刷新审查（2026-09-13）

## 本次修改

- 首页只展示本地课表，不显示课表登录过期、同步状态、上次同步或刷新按钮。首次使用从首页进入课表页获取数据。
- 课表页提供手动刷新、同步结果、上次成功时间和登录入口。登录过期不影响缓存读取；没有课程的周也不再误报“从未同步”。
- 移除启动时的教务登录态探测、启动课表刷新，以及登录/开启提醒时的周期课表任务注册。启动时取消旧版本遗留的任务。
- 课程提醒独立每 12 小时从本地缓存重新安排，不依赖课表网络同步。
- 首页与考勤页支持下拉刷新考勤，刷新中禁止重复点击。考勤页切换月份后加载对应月份，刷新期间固定查询范围。
- 考勤接口明确返回会话过期时，尝试一次现有 SSO 会话续期并重试；续期有时间和跳转次数限制，不清除 Cookie，不输入账号密码。SSO 本身过期时仍需要用户在登录页重新登录。
- 学生系统登录成功后刷新考勤，教务系统登录成功后刷新课表，修复原先两个系统登录均刷新课表的错误。
- 月度汇总和刷卡流水均成功才显示刷新成功。首页也显示考勤刷新失败原因和重新登录入口；网络异常保留缓存。
- 课表、考勤的“今日”缓存订阅随本地日期切换，修复应用跨天保持运行后仍显示启动当天数据的问题。
- HTTP 客户端从共享 builder 的副本构建，避免重复叠加 Cookie 拦截器；保留接口自己的 Referer。

## 真实网页核对

用户在浏览器中手动登录学生系统。通过“出勤记录 → 学生进出历史记录”，验证以 `YYYY-MM-DD` 填写相同的开始和结束日期能返回当天进出记录；网页自身存在分页。没有导出账号、密码、Cookie 或个人记录到项目文件。

这验证了网页查询条件，不能替代 Android WebView 登录态过期后的整条恢复链路实测。

## 其他发现（未在本次扩大修改）

1. **P1：首次识别学号可能导致刚同步的课表不可见。** `ScheduleRepositoryImpl.persist()` 先用旧 `accountHash` 写课程与同步元数据，随后调用 `onStudentIdDiscovered()` 切换账号分区；旧分区的数据没有迁到新分区。首次同步前尚未设置学号时可以触发。应在完整校验后用已识别账号写入目标分区，并补账号切换回归测试。
2. **P2：刷卡流水只取第一页。** `StuPunchDataSource.request()` 固定 `page=1, limit=500`，未读取 `count` 或继续翻页。记录超过单页上限，或服务端限制实际页大小时，历史记录可能缺失；无日期过滤的回退路径也有相同限制。应先收齐并校验所有页，再替换缓存。
3. **P2：部分流水解析失败仍可整体成功。** `StuPunchParser.parse()` 使用 `mapNotNull`，只在所有行都无法解析时失败；一部分行解析失败时仍会返回成功，随后替换整个日期范围的缓存，可能使进出配对不完整。应拒绝不完整数据或显式保留旧缓存并报告部分失败。

4. **P2：Android 8 的应用内更新兼容性。** 最低 SDK 是 26，但 `ApkVerifier` 直接使用 API 28 才提供的 `signingInfo`、`apkContentsSigners` 和 `longVersionCode`；Android 8 上包校验可能失败。应增加版本分支或使用兼容 API。
