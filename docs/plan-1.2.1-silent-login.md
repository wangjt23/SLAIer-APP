# 1.2.1 静默自动登录计划

1. App 在前台发现考勤会话过期时，使用离屏 WebView 完成已有认证流程，只展示“正在自动登录…”提示，不创建网页浮层。
2. 成功后核验学校会话并刷新考勤；失败、人机验证、网络错误或 30 秒超时，提示“自动登录失败，请自行登录”，暂停自动尝试。
3. 用户点击考勤或设置中的登录按钮才打开网页，并取消正在进行的静默认证。手动页面不自动提交保存的密码；确认手动登录成功后恢复后续自动登录能力。
4. App 离开前台、关闭自动登录或清除凭据时取消离屏认证并销毁 WebView。一次认证只提交一次密码，不绕过验证码。
5. 以虚拟页面回归测试验证两步登录、SSO 已有效、验证码、网络/TLS 失败、超时、取消、重复提交保护与最终会话核验；运行全量单元测试、Release 构建和差异检查。
6. 交付正式签名试用包 `dist/slaier-1.2.1-silent-login.apk`（versionCode 10），核对包内版本、签名和校验文件，等待用户试用确认；不暂存、提交、打标签、推送或发布。

## 试用反馈修复：会话有效后仍等待自动登录

- 发现原流程只在网页加载完成并落到指定路径后探活，没有观察并行考勤请求已确认的登录成功；等待网页回调可能拖至超时。
- 改为与网页并行执行实时会话检查；本轮考勤请求确认会话有效，也会立即结束认证并销毁离屏 WebView。旧的缓存登录状态和其他系统的登录状态不作为成功证据。
- 探活请求禁止缓存并支持取消，单次请求上限 5 秒；空响应及保留的旧 AUTHENTICATED 状态不视为新的登录证据。较早的探活失败不覆盖其等待期间新确认的登录成功。
- 新增网页尚未加载完成、非预期落地路径、JS 回调无响应、成功/超时竞争、旧认证证据排除及 HTTP 取消回归测试。最终共 275 项测试通过，0 失败、0 错误、0 跳过；Release 构建和签名验证通过。
- 更新同名 1.2.1 / versionCode 10 试用 APK 及其 SHA256，未提交、打标签、推送或发布。

- 使用跟随深浅主题的紧凑圆角浮层、状态图标与进度环，模拟器中已检查两套主题。
- 移除首页无课卡片中的“打开原网页”按钮。最终试用包构建及正式签名校验通过。
- 用户已确认最终效果，并授权提交、标签、推送及通过 GitHub 网页正式发布 1.2.1。
